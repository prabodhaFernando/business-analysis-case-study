# Business Analysis Case Study: QuickMart

> Note: QuickMart is a fictional business created for learning and portfolio purposes.

## What is the project?
A business analysis case study for a small retail shop that wants to replace its paper-based sales and stock records with a simple system.

## What problem does it solve?
QuickMart records all sales and stock in a paper notebook. This causes frequent mistakes, makes it hard to know when items are running low, and takes the owner about an hour every evening to total the day’s sales. The owner wants a simple system that tracks sales and stock automatically and produces a daily report.

## Stakeholders
| Stakeholder | Role | What they need |
|---|---|---|
| Shop owner | Decision maker, main user | Daily sales report, low-stock alerts |
| Cashier | Daily user | Fast, simple sales entry |
| Stock keeper | Daily user | Easy way to add and update stock |
| Customers | Indirect | Short waiting time, correct bills |
| Suppliers | Indirect | Clear, timely reorders |

## Business Requirements

### Business Objectives
1. Reduce the time spent totaling daily sales from 1 hour to under 10 minutes.
2. Reduce recording mistakes in sales and stock.
3. Alert the owner when items are running low.

### Functional Requirements
| ID | Requirement | Priority |
|---|---|---|
| FR1 | Users must log in with a username and password | High |
| FR2 | The system must let the stock keeper add, update, and delete items | High |
| FR3 | The system must let the cashier record a sale and calculate the total bill | High |
| FR4 | The system must reduce stock automatically after each sale | High |
| FR5 | The system must show a low-stock warning when an item falls below a set level | High |
| FR6 | The system must produce a daily sales report for the owner | High |
| FR7 | The system should let the owner view sales by date range | Medium |
| FR8 | The system should record supplier details for each item | Low |

### Non-Functional Requirements
| ID | Requirement |
|---|---|
| NFR1 | Recording a sale should take less than 30 seconds |
| NFR2 | Only authorized users can access the system |
| NFR3 | Data must be backed up daily |
| NFR4 | Staff should be able to learn the system in under one hour |

### Scope
- **In scope:** sales entry, stock management, daily reports, low-stock alerts.
- **Out of scope:** online ordering, customer loyalty program, accounting and payroll.
